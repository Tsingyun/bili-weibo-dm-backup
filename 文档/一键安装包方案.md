改动清单（5 处）：

1. **`启动.cmd`**（新增，项目根）—— 便携包唯一入口，纯 ASCII。**薄壳**：只做 `cd /d "%~dp0"` +
   校验 + 转调 `scripts\webui.ps1`，所有逻辑（找运行时、版本门槛、起服务、开浏览器）只在 PowerShell 那一份，避免两处提示漂移。
2. **`scripts/webui.ps1`** —— `Find-Node` 改为**内置优先**（`runtime\node\node.exe` → PATH → `C:\Program Files\nodejs`），
   并打印运行时来源（`内置` / `系统`）；工作区路径含中文或空格时**醒目提示**。
3. **`scripts/pack_portable.mjs`**（新增）—— 打便携包；原地逐文件覆写、zip 先写 `.tmp` 再换名；
   隐私扫描**复用 `build_skill.mjs --check`**（不另写一份黑名单，否则两套规则迟早漂移）。
4. **界面第 1 步**（`server.mjs` + `webui/`）—— `/api/state` 增加 `runtime` 字段；
   环境卡片改为「**运行环境**（内置/系统）」+「**工作区路径**（含中文空格则标注意）」；侧栏显示**真实服务地址**。
5. **`README.md`** —— 顶部新增「最省事的走法」；启动器清单加入根目录 `启动.cmd`。

### 发布方式：走 GitHub Release，不提交进仓库

| 做法 | 结论 |
|---|---|
| 把 zip 提交进仓库树 | ❌ 33 MB 二进制进 git 历史，**每次重建都再留一份**，仓库永久变大、clone 变慢；且与「仓库只放代码 + 文档」的既有约定冲突（`.gitignore` 已忽略 `/runtime/`、`/dist/`） |
| **GitHub Release 资产**（采用） | ✅ 单资产上限 2 GB、不污染历史，还有稳定直链 `…/releases/latest/download/dm-backup-portable.zip` |
| GitHub Actions 按 tag 自动构建 | ⏭ 未做：做了以后每次发版不用手动上传（CI 里下载 Node 官方包 → 跑 `pack_portable.mjs` → 传 Release） |

## 0. 结论

**能做成一个整体包，而且比想象中简单。** 因为这个项目**零第三方依赖**：

- 仓库里**没有 `package.json`**，也就没有 `node_modules`、不需要 `npm install`；
- 脚本只用 Node 内置模块（`node:http` / `node:fs` / `node:child_process` …）；
- 登录复用**系统自带的 Edge/Chrome**，不用打包浏览器。

所以「包含所需依赖与运行环境」这句落到实处，就是**往包里放一个 `node.exe`**（实测 83.0 MB，压完 32.6 MB）。

而且**除「装 Node」之外的每一步，代码里本来就已经做好了**——真正要补的只有一件事：**别让用户自己装 Node**。

## 2. 三种打包形态，怎么选

| | A. 便携一体包（zip） | B. 安装程序（单 exe） | C. 自解压单文件 |
|---|---|---|---|
| 用户拿到的 | 1 个 zip | 1 个 `Setup.exe` | 1 个 `.exe` |
| 用户动作 | 解压 → 双击 `启动.cmd` | 双击 → 向导 → 完成 | 双击（自解压并启动） |
| 体积 | **实测 33 MB** | 约 40 MB | 约 35 MB |
| 管理员权限 | **不需要** | 视模式（per-user 可不需要） | 不需要 |
| SmartScreen | 会拦（未签名） | 会拦（未签名） | 会拦（未签名） |
| 卸载 | 删文件夹 | 有卸载器（可问「要不要保留私信数据」） | 删文件夹 |
| 状态 | **已实现** | 未做（可选升级） | 未做 |

**结论：先做 A。** B 的体验更「像装软件」，但没有代码签名证书（要花钱）时 SmartScreen 一样会拦，
**体验差距没有想象中大**，而 A 不写注册表、不需要管理员、出问题最好解释。

### A 的变体 A2：不带 `node.exe`，首次运行自动下载
包体可降到 **< 1 MB**（`--no-runtime` 已支持该产物形态，但**下载环节尚未实现**）。
- 好处：包极小、升级方便。
- 代价：**首次必须联网**（国内直连 nodejs.org 有时很慢）→ 对「下载即用」是倒退。
- 建议：**主推 A（自带运行时）**，A2 只作为「极小包」选项，别默认。

## 3. 便携包的实际结构

```
dm-backup/                       ← 解压出来就这一个文件夹
├── 启动.cmd                     ← ★ 唯一需要双击的文件（纯 ASCII 薄壳）
├── 从这开始.txt                 ← 收件人第一眼看的（UTF-8 带 BOM，记事本不乱码）
├── runtime/node/
│   ├── node.exe                 ← 内置 Node 22（便携，不写注册表、不进 PATH）
│   └── LICENSE                  ← Node 自己的许可证（**分发二进制必须带上**）
├── scripts/                     ← 代码（含 lib/、_skill/；不含 _explore/）
├── webui/                       ← 引导界面
├── 命令/<分类>/*.cmd            ← 16 个进阶启动器（保持仓库结构）
├── 文档/                        ← 补充说明
├── 查看备份.html
├── sessions.json                ← 已建好的**空白**会话清单（省掉「复制模板」那一步）
└── README.md · 使用说明.md · 使用限制.md · LICENSE
```

**命名刻意全 ASCII**（zip 名与包内根目录）。原因：解压时 Windows 资源管理器默认按
**压缩包名**建文件夹 —— 包名若是中文，等于给每个收件人都发了一个中文路径，
而这个项目一直在提醒「别放中文/空格」。所以宁可**容器英文、说明中文**。
（包内文件名仍是中文，如 `启动.cmd` / `命令/…`，已验证 UTF-8 标志位能正确解出。）

**包内不含**：`data/` `bili/` `sessions.json`（真实 uid）以外的任何数据、
`sessions.js`（由真实配置生成，含真 uid）、`.ocr-env/`（330 MB）、`.edge-profile/`、`scripts/_explore/`（开发测试）。

## 4. 从「下载」到「进入 Web UI」的完整流程

### 用户视角
1. 下载 `dm-backup-portable.zip`（约 33 MB）。
2. 解压到**纯英文、无空格的路径**（例如 `D:\dm-backup`）。
3. 双击 **`启动.cmd`**。
4. 首次可能弹 SmartScreen → 「更多信息」→「仍要运行」。
5. 黑色窗口打印：内置 Node 版本 / 工作区路径 / 「正在启动本地服务…」。
6. **浏览器自动打开** `http://127.0.0.1:<端口>/`，落在第 1 步「环境检查」。
7. 之后全在界面里点，按 7 步走完。
8. 结束时回黑窗口按 `Ctrl+C`。

### 系统视角

| 步骤 | 实际行为 |
|---|---|
| 双击 `启动.cmd` | `chcp 65001` → `cd /d "%~dp0"` → 校验 `scripts\webui.ps1` 存在 |
| 找运行时 | `runtime\node\node.exe`（内置优先）→ PATH → `C:\Program Files\nodejs\node.exe` |
| 版本门槛 | 低于 18 直接报错并说明去哪升级 |
| 起服务 | `node scripts/server.mjs --port 8787 --open` |
| 端口 | 被占或被拒 → 自动 +1 重试（最多 20 次）；**实际地址打印在窗口里、也显示在界面侧栏** |
| 开浏览器 | 用系统默认浏览器打开该地址（打不开也不影响，地址已在窗口） |
| 界面 | 第 1 步做环境自检，逐条说清「还缺什么」 |

## 5. 界面里「一步一步」怎么走

7 步引导对新手的友好度已经够，最有价值的是把**最容易卡住的地方**前置到第 1 步：

| 步骤 | 现状 |
|---|---|
| 1 环境检查 | 已补：**运行环境**（内置还是系统 Node，直接给结论）、**工作区路径**（含中文/空格则标「注意」并给出建议路径）、侧栏显示**真实服务地址** |
| 2 授权登录 | 开专用浏览器窗口登录；走不通时可手动粘 Cookie（界面内有逐步教程） |
| 3 选择会话 | `sessions.json` 已预建，这里填对方数字 ID 即可（输入框提示里写了去哪抄） |
| 4 备份 | 勾平台 → 选模式/范围 → 实时日志 |
| 5 加载他人备份 | 拖 zip 进来，只读 |
| 6 导出 | 多种格式 + 打码 |
| 7 查看与维护 | 打开查看页、单步运行、任务列表 |

> 原则：**凡是黑窗口里能打印的提示，界面里都要能看到**。新手不会读控制台。

## 6. 注意事项（都会真踩到）

1. **SmartScreen / 杀软**：未签名的 `.exe`/`.cmd` 会被拦；「启动就监听端口 + 打开浏览器」这个行为特征还可能被杀软误报。
   → 文档里写清「更多信息 → 仍要运行」；介意的话只能买代码签名证书。
2. **路径别含中文和空格**：实测不影响程序启动，但个别环节（浏览器调试端口、命令行传参）历史上出过问题。
   → 已实现的是**提示不阻断**（界面卡片 + 启动器警告）。**故意不阻断**：能把用的用户挡在门外。
3. **端口 8787 在本机实测过 `EACCES`（保留段）**：已有自动后移，界面必须显示**真实地址**（已做）。
4. **架构**：`node.exe` 必须是 **win-x64**；ARM 设备靠系统 x64 模拟能跑，但不保证。
5. **升级不能碰数据**：覆盖代码时**原地逐文件覆写**，绝不整目录删除——
   目录被浏览器/杀软持句柄时 `rm -rf` 会卡死并留下**缺文件的残包**（本项目踩过）。
6. **OCR 是唯一的大头（约 330 MB）**：不塞进主包，改由界面/启动器按需安装。
7. **`.cmd` 编码规则**：纯 ASCII 最稳；含中文必须 UTF-8 **带 BOM**（否则 Win PowerShell 5.1 乱码）。
   `.ps1` 必须 UTF-8 **带 BOM**（改完要复核前三字节是 `EF BB BF`）。
8. **许可要随包（两套！）**：MIT 要求版权声明随副本分发 →
   ① 我们自己的 `LICENSE` + `使用限制.md` 必须在包里；
   ② **打了 `node.exe` 就等于在分发 Node.js**，必须把 Node 自己的 `LICENSE`（MIT + 第三方聚合，约 145 KB）
   放在 `runtime/node/LICENSE`。少了 ②，①写得再全也不合规。
   → 打包脚本已做成**硬约束**：找不到运行时许可证就**拒绝打包**（可用 `--runtime-license` 指定）。
9. **包里绝不能有真实凭据/数据**：`sessions.json` 只放**空白模板**，且打包脚本会**断言模板里 uid 为空**。
10. **首次运行会写盘**：`sessions.json` / `data/` / `bili/` / `.edge-profile/`
    → 默认落在解压目录（便携包的天然优势），别装进 `Program Files`。

- 不打包 `data/` `bili/` 与任何真实会话配置（隐私）。

## 9. 自动打包流水线（2026-09-25 新增）

> 背景：《发行版本一致性审计》P0 —— 便携包是构建产物、不进 git，靠人工重打，
> 结果 Release `v0.1.0` 落后源码两天才被发现。根治办法：**发版即打 tag，tag 触发自动打包发布**。

### 流程

```
git tag v0.1.x && git push origin v0.1.x
        │
        ▼
.github/workflows/portable-release.yml   （windows-latest）
  1. checkout（tag 指向的那一份源码）
  2. setup-node 22 → 定位 node.exe 与它的 LICENSE（缺许可证直接失败）
  3. node scripts/pack_portable.mjs --node … --runtime-license … --out dist
     （内部先跑 build_skill --check 隐私扫描，不过就中止）
  4. 复核 zip 存在且 >10 MB
  5. gh release create <tag> dist/dm-backup-portable.zip
     （已存在则退化为 --clobber 覆盖上传）
```

### 设计要点

- **发布物与 tag 一一对应**：包永远由 tag 指向的 commit 打出，「包落后源码」在机制上不可能再发生。
- **`{{NODE_VERSION}}` 占位符**：`.github/portable-release-notes.md` 里的运行时版本是占位符，
  发布步骤用真实 `node --version` 替换后再作为 release notes —— 文档不会写死一个以后对不上的版本号。
- **许可证硬约束在 CI 里同样生效**：runner 上找不到 node 同目录的 `LICENSE` 会立刻失败
  （分发二进制不带许可证不合规，见第 6 节第 8 条）。
- **手动触发**（workflow_dispatch）只打包、传 artifact，**不发布** —— 用来验证打包链路不产生噪音版本。
- **README 的 `releases/latest/download/dm-backup-portable.zip` 链接不用改**：资产名没变，
  「永远指向最新 Release」从此就真的等于「最新源码的稳定版」。

### 与本地手打的分工

| 场景 | 用哪个 |
|---|---|
| 正式发版 | 推 tag（CI 自动打包 + 发布） |
| 本地验证打包链路 / 给朋友手动发一份 | `node scripts/pack_portable.mjs`（产物在 `../dist/`，**不自动发布**） |
