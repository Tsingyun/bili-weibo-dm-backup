## 1. 任务触发时间

**每周一早上 08:00**（本机时区 GMT+8），一周一次。

- 改成「每天」：`命令/配置与定时/注册定时更新.cmd -Daily -At 21:30`
- 改成「每周一、周四」：`命令/配置与定时/注册定时更新.cmd -DaysOfWeek Monday,Thursday`
- 只改时间：`命令/配置与定时/注册定时更新.cmd -DaysOfWeek Monday -At 09:30`
- 参数说明：`-DaysOfWeek` 支持 `Monday`…`Sunday`，多个用英文逗号分隔；`-At` 是 24 小时制 `HH:mm`。

> 改频率/改时间都需要**先取消再重新注册**：双击 `命令/配置与定时/取消定时更新.cmd`，再按上面的命令注册。
> 注册时会自动把旧名字的任务（`私信备份每日自动更新`）一起清掉，不会留下僵尸任务。

## 3. 需要抓取 / 同步的内容范围

每次运行按固定顺序走 6 步（`scripts/auto_update.ps1`），两个平台各跑一遍：

| 步骤 | 内容 | 说明 |
|---|---|---|
| 1 | **增量抓取** | 私信文本、图片、卡片、表情（表情包会映射成可读名称）、撤回消息的原文；按消息 id / seqno 去重，**只追加新增，不重写旧数据** |
| 2 | **图内文字 OCR** | 对新图片做文字识别，写进 `ocr.json`（本地跑，不联网） |
| 3 | **图片内容描述 VLM** | 对「没有文字的照片」生成一句描述，写进 `vlm.json`；用智谱免费模型，**没配 Key 会自动跳过，不会报错中断** |
| 4 | 图片压缩 | **默认关闭**（不可逆操作，要显式 `-Compress` 才做） |
| 5 | **索引快照** | 在 `snapshots/<会话>/<时间戳>/` 存一份当时的索引（可回滚） |
| 6 | **一键体检** | 检查数据一致性 / 缺失图片等，结果写进日志 |

当前数据量（2026-09-21 实测）：

| 平台 | 消息 | 图片 | OCR 条目 | VLM 描述 |
|---|---|---|---|---|
| 微博 | 7,925 | 1,962 | 846 | 175 |
| B站 | 2,912 | 427 | 402 | 89 |

想少跑一些（注册或手动运行时都可以带）：

| 目的 | 参数 |
|---|---|
| 只更新数据，跳过所有图片索引（最快） | `-SkipIndex -SkipVlm` |
| 只跳过图片描述、保留 OCR | `-SkipVlm` |
| 只更新微博 / 只更新 B站 | `-Sessions weibo` / `-Sessions bili` |
| 顺带压缩新图片（不可逆） | `-Compress` |

## 4. 备份的存储方式

**全部存在本机磁盘**，不上传任何服务器、不用云盘、不用云数据库。

```
<工作区>/
├─ data/                     微信…微博的备份（会话 key = weibo）
│  ├─ messages.json/.js      全部私信（json 给程序读，js 给网页读）
│  ├─ images/                图片与卡片封面
│  ├─ faces/ + faces.js      表情包原件 + 名称映射
│  ├─ ocr.json / vlm.json    图内文字 / 图片描述
│  ├─ meta.json              条数、时间范围、最新一条 id
│  ├─ raw/                   原始接口响应（可清空，目录保留）
│  ├─ cookie_header.txt      ⚠ 登录凭据，等同账号密码，不要外传
│  └─ glm_key.txt            ⚠ VLM 用的 API Key，不要外传
├─ bili/                     B站的备份（会话 key = bili），结构同上
├─ snapshots/<会话>/<时间戳>/ 索引快照（异常时可回滚）
├─ logs/
│  ├─ auto_<时间戳>.log      每次运行的完整日志，**只保留最近 60 份**
│  └─ auto_history.txt      一行一行的历史摘要（时间 / 成功失败 / 步骤数 / 失败数）
├─ search/dm_search.db       本地全文检索库（FTS5，不联网）
└─ exports/                  手动导出的 JSONL、表情包（定时任务不产出）
```

要点：

- **增量追加**：每轮只把新增消息写进去，历史条数只会增加，不会被覆盖或清空。
- **快照可回滚**：第 5 步会给当时的索引存一份，写坏了能退回上一版。
- **日志自动轮转**：`auto_*.log` 只留最近 60 份，不会无限增长。
- `数据/` 里没有任何逻辑代码，**代码与数据完全分开** —— 删数据不会影响程序，删代码不会丢数据。

## 5. 更新失败时的处理

### 怎么知道失败了

- **退出码**：`0` = 全部步骤成功；`1` = 至少一个步骤失败。
- **日志**：失败明细在 `logs/auto_<时间戳>.log`，每一步都标了 `[ok] 耗时 x.xs`
  或 `[NG] 退出码 N`；文件末尾会列出所有失败步骤。
- **摘要**：`logs/auto_history.txt` 最后一行能看到最近一次的 `成功/失败`、`steps`、`fail`。
- **任务结果码**：`命令/配置与定时/注册定时更新.cmd -Status` 里的「结果码」`0` 表示成功，其它值表示有步骤失败。

### 常见退出码含义

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 通用失败（某一步报错） | 看 `logs/auto_*.log` 里标 `[NG]` 的那一步 |
| 2 | 没有登录凭据 | 手动双击一次 `命令/备份与更新/更新备份.cmd` / `命令/备份与更新/更新B站备份.cmd` 完成登录 |
| 3 | 登录过期 | 同上，重新登录一次即可 |
| 4 | 还没填 `sessions.json` | 按 `使用说明.md` 第 2 节填好对方 uid，再双击 `命令/配置与定时/生成会话清单.cmd` |

### 失败会不会丢数据

**不会。** 抓取是增量追加：

- 抓取中途失败 → 已经写进去的新消息保留，未抓到的下次继续；
- 某一步（如 OCR / VLM）失败 → 只影响那一步的索引，**消息本体已经存好**；
- 图片压缩是唯一的不可逆步骤，而且**默认关闭**。

### 重试与兜底

| 情况 | 处理方式 |
|---|---|
| 想立刻重跑一次 | 双击 `命令/配置与定时/注册定时更新.cmd -RunNow`，或直接跑 `scripts\auto_update.ps1` |
| 到点时电脑关机 / 休眠 | `StartWhenAvailable=True`，下次开机后自动补跑一次 |
| 上一次还没跑完又到点了 | `MultipleInstances=IgnoreNew`，直接跳过新一轮（避免两个抓取脚本抢同一个浏览器） |
| 卡住不动 | `ExecutionTimeLimit=PT3H`，跑满 3 小时会被强制结束，不会挂到第二天 |
| 任务被误删 / 换了机器 | 双击 `命令/配置与定时/注册定时更新.cmd` 重新注册一次即可 |
