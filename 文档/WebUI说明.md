# WebUI 说明 —— 图形界面的架构与实现

> 这份文档回答四件事：**它是什么 / 怎么分层的 / 数据存在哪 / 哪些地方最容易踩坑**。
> 想直接用，看 `使用说明.md` 第 16 节就够了；这份是给要改它的人看的。

---

## 一、它是什么

一个**只在本机跑**的小网页：双击 `命令/查看与导出/启动WebUI.cmd` → 浏览器打开 `http://127.0.0.1:8787/`
→ 7 步引导（环境检查 → 授权登录 → 选会话 → 选范围备份 → 加载他人备份 → 导出 → 查看与维护）。

覆盖三件事：

| 能力 | 说明 |
|---|---|
| **备份** | 授权登录（不碰密码）→ 选会话与时间范围 → 本地抓取增量/全量 |
| **加载他人备份** | 拖入别人分享的 `.zip` / 文件夹 / `messages.json`，解到 `imported/`，**只读**浏览 |
| **导出** | 选会话 / 时间范围 / 全部，输出 `jsonl` · `json` · `csv` · `md` · `html` · 打包 zip |

**技术底线**（每条都是硬要求，不是"尽量"）：

1. **零依赖**。只用 Node 内置模块（`node:http` / `fs` / `child_process` / `zlib` / `node:string_decoder`）。
   目标使用者是"会双击 `.cmd` 的人"，不能让他们先 `npm install`；连 zip 都是自己写的（见第四节）。
2. **只监听 `127.0.0.1`**。绝不用 `0.0.0.0`。
3. **不重写业务逻辑**。抓取、OCR、导出这些**已经存在**的脚本一律通过子进程调用，
   WebUI 只做「串起来 + 显示状态 + 收参数」。见第三节的分层理由。
4. **不碰密码**。登录靠"开一个干净浏览器让你自己登"，程序只通过 CDP 读 Cookie。

## 二、整体架构

```
┌──────────────────────────── 浏览器 ────────────────────────────┐
│  webui/index.html + style.css + app.js                         │
│  只做三件事：显示状态、把用户的选择**原样**传下去、把日志流出来    │
│  · 写接口一律带 X-DM-WebUI: 1 这个自定义头                       │
│  · 日志用 EventSource 订阅 /api/job/stream（SSE）               │
└───────────────────────────────┬────────────────────────────────┘
                                │ HTTP（127.0.0.1，同源）
┌───────────────────────────────▼────────────────────────────────┐
│  scripts/server.mjs           ← 唯一的服务端进程（零依赖）        │
│  ├─ 静态文件：webui/ data/ bili/ imported/ exports/ + 查看备份.html│
│  ├─ 只读接口：state / jobs / job / job/stream / login/status     │
│  │            exports / imported / download / preview           │
│  ├─ 写接口：session / login / fetch / run / job/kill            │
│  │           export / import / import/upload / imported/delete   │
│  └─ 自己的事只有三件：读盘、串参数、spawn 子进程                   │
└───────────────┬───────────────────────────────┬─────────────────┘
                │ import                        │ child_process.spawn
┌───────────────▼──────────────┐   ┌────────────▼──────────────────────────┐
│  scripts/lib/                │   │  已有的业务脚本（**完全没改逻辑**）      │
│  ├─ paths.mjs    路径/安全    │   │  update.mjs / bili_update.mjs   抓取   │
│  ├─ jobs.mjs     任务与日志流  │   │  sync_faces.mjs / bili_faces.mjs 表情  │
│  ├─ zip.mjs      自写 zip     │   │  image_ocr.py / image_vlm.py     索引  │
│  ├─ export_engine.mjs 导出    │   │  snapshot.mjs / doctor.mjs       快照/体检│
│  └─ import_backup.mjs 导入    │   │  run_pipeline.mjs  ← 统一入口（串起来）  │
└──────────────────────────────┘   │  login.mjs         ← 授权登录           │
                                   └───────────────────────────────────────┘
                │ 读写
┌───────────────▼─────────────────────────────────────────────────┐
│  数据：data/ · bili/（本机私信）   imported/（他人备份，只读）      │
│        imports/（待导入包）  exports/（导出产物）  .webui/（运行状态）│
└─────────────────────────────────────────────────────────────────┘
```

### 为什么是这种"薄前端 + 薄服务端 + 复用脚本"

备选的写法是「把抓取逻辑在 server.mjs 里再实现一遍」。那样做会立刻出两个问题：

* **两套口径**。比如「一天」的定义是 `05:00 → 次日 05:00`（凌晨 0-5 点算前一天），
  这个规则已经有 3 处实现、6 处消费者（见 `使用说明.md` 第四节）。
  一旦 WebUI 里再抄一份，改一处忘一处，两条路的统计数字就会不一样 —— 而这种 bug
  用户是看不出来的，只会觉得"这软件算得不对"。
* **修 bug 要修两遍**。接口一变、限流一调整，得同步改两个地方。

所以这里定了条规矩：**WebUI 不产生新的业务判断**。
所有过滤、分类、分页、打码，全部调用既有模块（`msg_kind.mjs` / `export_engine.mjs` …），
前端只负责把选择传下去。验证脚本里专门有一条断言在盯这件事：
**HTTP 接口返回的条数，必须和进程内直接调 `collect()` 的条数逐个相等**。

## 三、模块划分

### 前端（`webui/`，3 个文件，无构建步骤）

| 文件 | 职责 |
|---|---|
| `index.html` | 7 步导航 + 7 个面板。纯静态，没有打包器、没有框架 |
| `style.css` | 深色主题、栅格布局、日志区 / 预览区 / 拖放区样式 |
| `app.js` | `api()` 封装（自动加 `X-DM-WebUI` 头）、各面板渲染、`watchJob()` 订阅 SSE、`uploadFile()` 上传 |

前端刻意保持"薄"：**不做任何数据加工**。比如 CSV 里怎么转义、`05:00` 怎么划天，
全部在服务端已定；前端只把 JSON 铺成 DOM。

### 服务端（`scripts/server.mjs`）

按**关注点**分块，而不是按路由分：

| 块 | 内容 |
|---|---|
| 守卫 | `guardWrite()`：检查 `X-DM-WebUI: 1` + `Origin` 是否本机（见第四节 CSRF） |
| 状态汇总 | `buildState()`：会话清单 + 每个会话的条数/时间范围/登录态 + 环境探测 |
| 任务流 | 全部转交 `lib/jobs.mjs`；`/api/job/stream` 是 SSE |
| 导出 | 全部转交 `lib/export_engine.mjs` |
| 导入 | 全部转交 `lib/import_backup.mjs` |
| 静态 | `serveStatic()`：白名单前缀 + `webui/` 兜底（见第四节那个 404 坑） |

### 共用模块（`scripts/lib/`）

| 文件 | 解决的问题 |
|---|---|
| `paths.mjs` | 统一的目录常量 + `safeJoin()`（拒绝绝对路径和 `..`）+ 原子写 JSON（`.tmp` → rename） |
| `jobs.mjs` | 子进程任务：流式收集输出、环形缓冲（留最近 4000 行）、SSE 订阅、终止、上限 30 个并淘汰最老的非运行中任务 |
| `zip.mjs` | 自写 zip 读写（见第四节） |
| `export_engine.mjs` | 6 种格式的渲染 + 过滤（会话 / 时间 / 类型 / 条数 / 打码）+ bundle 打包 |
| `import_backup.mjs` | 单文件 / zip / 目录三种入口 → 识别数据目录 → 解包 → 补包装文件 → 登记会话 |

### 编排层

| 文件 | 职责 |
|---|---|
| `run_pipeline.mjs` | 一条命令跑「抓取 → 表情 → OCR → VLM → 快照 → 体检」。缺环境**只跳过不报错**，并在日志里说清跳了什么 |
| `login.mjs` | 授权登录：找一个 Edge/Chrome → 用独立配置目录 + 远程调试端口拉起 → 读 Cookie → 校验 → 落盘 |

## 四、数据存储方案

### 目录与用途

| 目录 | 内容 | 能不能删 | 入不入 Git |
|---|---|---|---|
| `data/` `bili/` | 本机私信本体（消息 / 图片 / OCR / VLM / Cookie） | **不能**（删了就得重抓） | ❌ 隐私红线 |
| `imported/<批次>/` | 别人分享的备份，**只读** | 能（界面上删） | ❌ 同样是别人的私信 |
| `imports/` | 拖进来待导入的原始压缩包 | 能 | ❌ |
| `exports/` | 导出产物 | 能 | ❌ |
| `.webui/state.json` | 界面运行状态（上次抓取 / 导出时间、批次名） | 能 | ❌ 本机痕迹 |
| `webui/` | **前端源码**（唯一的"程序"目录） | 不能 | ✅ 入库 |

### 三条存储规则

1. **导入 = 只读副本，与本体物理隔离。**
   导入的数据解到 `imported/<批次>/`，在 `sessions.json` 里标 `imported: true` + `readonly: true`。
   会写文件的操作（抓取 / OCR / 压缩 / 快照）对它一律拒绝，
   只有「体检」放行（它不写任何文件）。
   👉 **为什么隔离**：不隔离的话，用户"打开别人的备份"之后随手点一下"开始备份"，
   就会拿自己的登录态去往别人的数据目录里写东西 —— 既污染数据，也可能把两边的记录混在一起。

2. **状态与数据分开。**
   `.webui/state.json` 只存"上次干了什么"，**从不存消息内容**。丢了顶多少一条提示。

3. **写 JSON 一律原子替换。**
   `paths.mjs` 的 `writeJson()` 走 `.tmp` → `rename`。
   直接覆写会在断电 / 强杀时留下半个文件，而 `sessions.json` 半个文件 = 程序再也起不来。

### 会话清单是唯一真相源

`data/` 和 `bili/` 之所以能被"切换"，全靠项目根的 `sessions.json`（`peer` / `self` / `dir` / `platform`）。
`imported/` 里的每一批也会写进这里，然后重新生成 `sessions.js`，
于是**查看页顶部的切换按钮里就会多出这些导入的备份**，和本机数据一样能翻。

> ⚠️ 一处**踩过的坑**：`loadSessions()` 原来只透传部分字段，
> `imported` / `readonly` 在归一化那一步被丢掉了。
> 结果 `if (S.imported)` **永远是 false** —— 只读保护写了、看起来在、实际一条都没生效
> （WebUI 的抓取拒绝、`run_pipeline` 的写步骤拒绝全部形同虚设）。
> 这是跑端到端验证脚本才发现的：脚本真对导入会话发起了抓取，返回 200 而不是 400。
> **教训：给会话加字段时，一定要在 `loadSessions()` 里同步透传。**

## 五、关键技术难点

### 1. 零依赖的 zip（写 + 读）

不能依赖 `Compress-Archive` / `7z`（换个环境就没有），所以自己实现：

* **写**：每个条目 `zlib.deflateRawSync` 压缩后手写 local file header，再收集中央目录 + EOCD；
  文件名用 UTF-8，**必须置通用标志位 `0x0800`** —— 不置的话 Windows 资源管理器
  会把中文文件名解成乱码。
* **读**：从尾部回扫找 EOCD（`0x06054b50`），再按中央目录逐条读；
  **明确拒绝 zip64 和加密包**（各写一条清晰的错误，而不是解出乱码文件）。
* 单个条目上限 512 MB，防止一个畸形包把内存吃光。

### 2. 子进程日志的流式搬运（SSE）

抓取要跑几分钟，用户必须**实时看到**日志，否则会以为卡死。

* `spawn` 时把 stdout/stderr 用 `StringDecoder('utf8')` **流式解码**。
  直接用 `chunk.toString()` 会在多字节字符正好被切断时吐出 `�`
  （中文日志尤其容易撞上，因为一个汉字 3 字节、缓冲区边界不认字）。
* 输出进环形缓冲（保留最近 4000 行），同时推给所有订阅者；`/api/job/stream` 用 SSE，
  前端 `EventSource` 接；断线重连时带 `since=<已收到的行数>`，**只补发新的行**。
* 任务结束推一帧 `t: "status"` 然后关流，前端据此把按钮恢复。

### 3. CSRF：`127.0.0.1` 上的服务必须防

本地服务并不是"只有我能访问"——**你打开的任何一个恶意网页，都能向你本机的 8787 端口发请求**
（浏览器的同源策略只挡"读响应"，挡不住"发请求"）。所以：

* 写接口要求自定义头 `X-DM-WebUI: 1`。**跨站请求带不上自定义头**（会触发预检，而被拒），
  这一条就挡住了绝大多数 CSRF；
* 再校验 `Origin`：必须缺失（非浏览器客户端）或 `127.0.0.1` / `localhost`。
  `Origin` 存在但不是本机 → 直接 403。

验证脚本**两个方向都测**：不加头必须 403、跨站 Origin 必须 403，
而**加了头 + 同源必须放行** —— 只测"该拒的拒了"会漏掉"该放的也拒了"这种把自己锁死的情况。

### 4. 路径穿越

静态服务和下载接口都收用户传来的路径。`safeJoin()` 统一处理：
`path.resolve` 之后必须仍在根目录之内；任何绝对路径或含 `..` 的一律拒绝。
编码形式的穿越（`%2e%2e%2f`）也要挡住 —— 因为路径是**先 `decodeURIComponent` 再校验**的。

### 5. 首页与静态资源的路径错位（真踩过）

首页是从 `/` 提供的（不是 `/webui/`），而 `index.html` 里写的是相对路径
`href="style.css"` / `src="app.js"`。浏览器于是去要 `/style.css` —— 落在白名单之外，404。

**现象很坑**：页面 HTML 正常返回、标题也正常，就是样式全丢、脚本全不执行，
看起来像"JS 写错了"，实际是资源压根没到。修法：白名单之外再兜一层
「`webui/` 下同名文件就给它」，同时不放松 `webui/` 之外的访问。
现在验证脚本里有 3 条断言专门盯这个（`/style.css` / `/app.js` 的 200 与前端的 `X-DM-WebUI` 头）。

### 6. 端口被占用 / 被系统保留

`EADDRINUSE`（重复双击）和 `EACCES`（端口落在 Hyper-V / WSL 保留段里，**Windows 上很常见**）
都会让 `listen` 直接抛错。`server.mjs` 现在会自动往后找 20 个端口，
并在横幅里打印**实际**地址。启动器也强调"别死记端口号，看那行『地址』"。

### 7. 复用既有脚本时的"口径一致"

导出走的是 `export_engine.mjs` 的 `collect()`，它内部调用 `msg_kind.mjs` 的
`msgKind()` / `maskText()` / `dayStart()` / `dayEnd()`。
于是导出、查看页、检索索引三处对"一天"的定义天然一致。

验证脚本里对这条盯得很紧，而且是**独立复算**：

* HTTP 预览的条数 == 进程内 `collect()` 的条数（证明 HTTP 层没吃掉 `limit`）；
* `since = until = 同一天` 的条数 == 用**纯 `Date` 算术**算出的 `[05:00, 次日 05:00)` 条数
  （不复用 `dayStart()`，否则等于拿被测函数验证它自己）。

### 8. 导入端的"包长得不一样"

别人分享来的可能不是本程序导出的包，所以识别分三层：

1. 有 `manifest.json` 且 `format === "dm-archive-backup"` → 按它写的目录结构解；
2. 否则**嗅探** `<某目录>/messages.json|js`；
3. 再兜底：整个包就当一份数据。

解包前先 `stripCommonRoot()` 去掉公共顶层目录（否则 `我的备份/data/` 会被当成 `我/` 这个目录名）。
解完给每个数据目录补齐 `messages.js` / `faces.js` / `ocr.js` / `vlm.js` 四个包装文件 ——
**查看页是靠 `<script src>` 读数据的，只有 `.json` 打不开**。
最后一步才写 `sessions.json`；任何一步失败都**抛错回滚，不留下半个会话**
（验证脚本专门测了：喂一个不像备份的 zip，必须 400 + 清单没被污染）。

### 9. 登录校验：接口必须和抓取用的是同一套

「暂时无法校验 · 连不上平台接口」这个提示曾经一直误报，真根因是**校验接口和抓取接口分家了**：

* 抓取走的是 `https://api.weibo.com/webim/query_primary_info.json`（`update.mjs` 的 `API_BASE`）；
* 校验当初写的是 `/chat/query_primary_info.json` —— 同一台机器、同一个 Cookie，
  `/chat/` 被网络路径上的透明网关挡成 **502**，而 `/webim/` 正常 **200**。
  于是"明明登录着"被报成"连不上接口"，而且**跟代理软件无关**（Clash 完全退出也照样）。

三条硬规则（都已写进回归断言，改坏会红）：

1. 校验的**主端点 = `API_BASE` + 抓取时那个接口**，不许再手抄一份 URL；
2. **多端点兜底**：主端点不通就试备用，只有一个给出明确结论才采用；
   全都连不上/被挡才算 `network`（这是"不知道"，不是"没登录"）；
3. **分类不能错**：5xx、返回 HTML（网关 502 / WAF 403）一律 `network`，
   只有平台自己的 JSON 说"不认这个 Cookie"才是 `expired`。

`network` 时不拦人：备份照常能跑（`update.mjs` 直接读本地 Cookie 文件发请求，
不依赖校验结论），已存的数据一点不受影响。万一自动登录那条路彻底走不通，
第 2 步「授权登录」里有**手动粘 Cookie** 的兜底教程（含 F12 逐步截图级说明），
存的位置和自动登录完全一样。

### 10. 多平台备份：任务在服务端排队（真踩过）

第 4 步同时勾「微博 + B站」点备份，本来应该两个都跑。旧实现是：

```js
for (const s of chosen) { jobs.push(startJob(...)); break; }   // ← 注释写着"前端会接力"
```

而**前端从来没实现接力** —— 于是只有第一个平台会跑，用户得手动取消微博、再单独选 B站。
"注释描述了不存在的行为"这种 bug，读单侧代码根本看不出来。

修法是把队列放进 `scripts/lib/jobs.mjs`：

* `startJob(spec, { queue })` → 任务建出来是 `queued` 状态，**不 spawn**；
  同队列里没有 `running` 时才轮到队首起跑，前一个 `close` 时自动 `pump` 下一个。
* 为什么必须串行：两平台同时抓会抢**同一个浏览器调试端口**（后起的连不上 CDP 直接失败）、
  抢同一块写盘，日志也会糊在一起分不清。
* 取消也要覆盖排队态：`killJob` 对 `queued` 直接把任务从队列摘掉。
  否则用户点「停止」杀了当前那个，队列里的下一个会**自己跑起来**（前端会把这轮剩下的任务一起取消）。
* SSE 那边：`queued` **不是终态**（否则第二个平台刚建出来就被当成"整轮结束"），
  并且状态从 `queued` 变 `running` 时要主动推一帧，前端才知道"轮到它了"。
* 淘汰旧任务时不能删 `queued` 的（队列里还留着它的 id，删了就永远卡住）。

回归里钉住了 7 条（`7.9`）：两个任务都建出来、同一时刻最多一个在跑、
排队中的任务能取消、取消后不留僵尸任务。

### 11. 体检的自动修复：只修「确定的」，且修完要敢说"没问题"

`doctor.mjs --fix` 只做确定性修复，现在有两类：

1. 按 `json` 重新生成 `js` 包装（查看页读的是 js）；
2. 清掉索引里的**孤儿键** —— `ocr.json` / `vlm.json` 里指向不存在图片的键。
   来源多是图片压缩 `webp→jpg` 转码后旧扩展名的键没迁走（同一张图留了两把键）。
   它没有任何用（按它找不到图），却让体检永远报「错误 1 项」，用户以为备份坏了。

两个细节值得记：

* 修之前先 `copyFileSync` 一份 `.bak-<时间戳>`，写回用**先写 .tmp 再改名**的原子替换；
* 修好的项要按 `errorText` 从报告里**划掉**再重算汇总 —— 否则刚修完还打印
  「合计：错误 1」，退出码仍是 1，自动更新脚本会一直判 NG（用户看到的就是"修了但没修好"）。

## 六、实现步骤（按依赖顺序）

如果想从零复刻一遍，顺序是这样的：

| # | 步骤 | 产出 | 关键点 |
|---|---|---|---|
| 1 | 共用底座 | `lib/paths.mjs` | `safeJoin` + 原子写。**先有它**，后面所有文件读写都走它 |
| 2 | 任务流 | `lib/jobs.mjs` | `StringDecoder` 流式解码 + 环形缓冲 + 订阅 |
| 3 | zip | `lib/zip.mjs` | UTF-8 标志位、拒绝 zip64 / 加密 |
| 4 | 导出引擎 | `lib/export_engine.mjs` | **复用** `msg_kind.mjs`，6 种格式 + bundle |
| 5 | 导入 | `lib/import_backup.mjs` | 三层识别 + 补包装 + 登记 + 回滚 |
| 6 | 编排 | `run_pipeline.mjs` | 缺失环境只跳过；退出码沿用 0/1/2/3/4 |
| 7 | 登录 | `login.mjs` | 独立配置目录 + 远程调试端口；**只读 Cookie** |
| 8 | 时间范围抓取 | 给 `update.mjs` / `bili_update.mjs` 加 `--since/--until` | 早于 `since` 就停止翻页 |
| 9 | 服务端 | `server.mjs` | 守卫 → 静态 → 只读接口 → 写接口 |
| 10 | 前端 | `webui/` 三件套 | 引导分步；`api()` 统一带头 |
| 11 | 启动器 | `webui.ps1` + `命令/查看与导出/启动WebUI.cmd` | `.ps1` 必须 **UTF-8 带 BOM**；`.cmd` 必须**纯 ASCII** |
| 12 | 打通分享 | 改 `build_skill.mjs` / `init.mjs` | 必须带上 `scripts/lib/` 和 `webui/`（见下） |
| 13 | 验证 | `scripts/_explore/verify_webui.mjs` | 真起服务、真发请求，129 条断言 |

> **第 12 步是最容易漏的一步。** `build_skill.mjs` 和 `init.mjs` 原来只扫 `scripts/` 的
> **顶层文件**，新加的 `scripts/lib/` 和 `webui/` 都不会进包 ——
> 分享出去的 Skill 里 `server.mjs` 会 `import` 不到 `./lib/*`，界面起来就是空白页。
> 而"少复制了 8 个文件"从外面**完全看不出来**，只能靠真跑一遍初始化才发现。
> 所以这两个脚本现在都显式处理子目录，`MANAGED_DIRS` 也加上了 `webui`。

## 七、怎么验证它没坏

```bash
node scripts/_explore/verify_webui.mjs      # 129 条断言，真起服务、真发 HTTP
```

覆盖 8 组：静态资源与穿越防护 · 状态接口 · CSRF（双向）· 列表接口 ·
预览口径对账（含 05:00 边界独立复算）· 6 种导出格式 + 下载 + 穿越 ·
导入（只读保护 / 补包装 / 坏包不留残迹 / 删除）· 副作用检查。

几个设计上的讲究：

* **自己挑空闲端口**起服务，跑完杀掉，不会撞上你正在用的那个；
* 导入测试会真写 `sessions.json`，所以脚本**开头备份、`finally` 还原**，
  中途崩了也不会在你的清单里留下一个假的"导入会话"；
* 全绿才清临时目录，**有失败就留着现场**（`scripts/_explore/_tmp/webui/`）；
* 本次测试导出的文件会按前缀 `wbtest-` 自清，不动你已有的导出。

回归（改了共用模块后建议一起跑）：

node scripts/_explore/verify_sessions.mjs    # 49 条（会话清单）
node scripts/_explore/verify_extras.mjs      # 114 条（有 1 条是既有失败：doctor --json 可执行）
node scripts/_explore/verify_daycut.mjs      # 118 条（05:00 划天口径）

## 八、已知边界

* **不支持 zip64**（单条 > 4 GB 或条目数 > 65535 的包），会明确报错而不是解出坏文件；
* **不支持加密 zip**，同样明确报错；
* **一次只跑一个抓取任务**：两平台同时跑会抢同一个浏览器调试端口（9333），
  所以 `/api/fetch` 一次只启动第一个，前端串行接着发下一个；
* **任务记录不落盘**：`.webui/state.json` 只存时间戳，重启后任务列清空 —— 日志是过程，不值得留；
* `verify_extras.mjs` 里 `doctor --json 可执行` 那一条是**既有失败**（与本次改动无关），
  看到它红不要误判成回归。
